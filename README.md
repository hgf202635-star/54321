# بوابة العطاء — Bawabat Al-Ataa

واجهة ويب عربية RTL لدليل معلوماتي للجهات والمنصات الخيرية والتطوعية في السعودية. هذا الإصدار هو **نموذج واجهة قابل للتشغيل** وليس خدمة إنتاج متصلة بقاعدة بيانات. لا توجد جهات حقيقية منشورة ولا روابط تبرع ضمن البيانات الافتراضية؛ وهذا مقصود لتجنب نشر معلومات غير مراجعة.

## المتطلبات
- Node.js 20 أو أحدث
- npm

## التشغيل محلياً
```bash
npm install
npm run dev
```
افتح الرابط الذي يعرضه Vite في الطرفية.

## البناء والاختبارات
```bash
npm run build
npm test
npm run preview
```

## الصفحات
- `/` الصفحة الرئيسية والتصنيفات
- `/directory` دليل الجهات والبحث والفلاتر والعرض الشبكي/القائمة
- `/faq` الأسئلة الشائعة والبحث
- `/reviews` نموذج تقييم مع توضيح أن الإرسال غير مفعّل
- `/suggestions` نموذج الاقتراحات والتحقق من المدخلات، دون ادعاء الحفظ
- `/errors` كتالوج مركزي لـ BA-100 إلى BA-140 مع بحث وفلاتر وتفاصيل
- `/admin` حالة صريحة بأن الإدارة غير مفعّلة
- صفحات غير موجودة تعرض واجهة 404

## ما يعمل في النسخة الحالية
- واجهة متجاوبة وRTL، الوضع الليلي، قائمة الجوال، بحث/فلاتر الدليل، بحث الأسئلة والأخطاء، فتح تفاصيل رموز الأخطاء، المفضلة المحلية، إشعارات قابلة للإغلاق، فحص أولي للروابط والمدخلات، ورسائل صريحة عن الخدمات غير المتاحة.
- المفضلة محفوظة محلياً في المتصفح فقط. لا تعني مزامنة أو حساب مستخدم.
- لا توجد إحصاءات أو تقييمات أو جهات حقيقية مصطنعة.

## ما يحتاج إلى إعداد قبل الإنتاج
1. إنشاء مشروع Supabase أو PostgreSQL وخدمات API موثوقة.
2. إعداد المصادقة والصلاحيات والتحقق في الخادم، وRLS، وترحيلات قاعدة البيانات، وسجل التدقيق.
3. إنشاء API فعلي للنماذج والتقييمات والبلاغات مع تحديد معدل الطلبات، وحماية CSRF عند الحاجة، والتحقق من المدخلات على الخادم.
4. إضافة بيانات الجهات من مصادر رسمية بعد مراجعة بشرية وتسجيل المصدر وتاريخ المراجعة. لا تنشر سجلّاً بحالة `verified` دون دليل مسجل.
5. إعداد سياسة الخصوصية وشروط الاستخدام الفعلية ومعلومات التواصل.
6. إعداد اختبارات متصفح Playwright ومراقبة أخطاء إنتاجية بعد إنشاء الخادم.

## متغيرات البيئة
لا توجد مفاتيح مطلوبة لتشغيل الواجهة الحالية. عند ربط الخدمات، أنشئ `.env.local` محلياً ولا تضع أسرار الإدارة أو مفاتيح الخادم في متغيرات `VITE_*` لأنها تُضمّن في حزمة المتصفح. يمكن استخدام `.env.example` كبداية إعداد فقط.

## البيانات
- `src/data.js`: التصنيفات، الأسئلة الشائعة، وكتالوج الأخطاء المركزي.
- `organizations` فارغة عمداً. `demoOrganizations` سجل توضيحي موسوم بوضوح ولا يُعرض ضمن الدليل المنشور.
- رموز BA داخلية خاصة بالمشروع، وليست رموزاً حكومية أو معياراً رسمياً.

## تنبيه أمني
فحص الرابط في المتصفح ليس بديلاً عن فحص خادمي، ولا يمنع وحده SSRF أو الروابط الخبيثة. قبل الإنتاج يجب التحقق من الروابط ومحتواها في خدمة آمنة، وتطبيق صلاحيات على الخادم، وعدم قبول حالة التحقق من الواجهة العامة.

## تشغيل المشروع من تابلت Android (بدون فتح index.html مباشرة)

المشروع يستخدم React وJSX، لذلك فتح `index.html` من مدير الملفات لن يشغّل التطبيق. يجب تشغيله عبر خادم تطوير أو بيئة سحابية.

### الطريقة الأسهل على التابلت: StackBlitz
1. نزّل ملف ZIP وافك ضغطه، أو ارفع المشروع إلى مستودع GitHub خاص بك.
2. افتح متصفح Chrome على التابلت واذهب إلى https://stackblitz.com/.
3. أنشئ مشروع Vite + React، ثم ارفع/انسخ ملفات المشروع مع الحفاظ على `src/` و`package.json` و`index.html` و`vite.config.js`.
4. انتظر تثبيت الحزم؛ عند نجاحها سيعرض المحرر معاينة مباشرة. إذا لم يبدأ الخادم، افتح Terminal وشغّل `npm install` ثم `npm run dev -- --host 0.0.0.0`.
5. لا تستخدم معاينة ملف HTML ثابتة؛ استخدم معاينة Vite التي تشغّل JSX.

### التشغيل على جهاز محلي يدعم Node.js
من الطرفية داخل مجلد المشروع:

```bash
npm install
npm run dev -- --host 0.0.0.0
```

افتح عنوان `http://localhost:5173` على الجهاز نفسه. للوصول من جهاز آخر على شبكة Wi-Fi نفسها، استخدم عنوان IP المحلي للجهاز الذي يشغّل Node.js مع المنفذ `5173`، مع مراعاة إعدادات جدار الحماية.

### البناء للإنتاج

```bash
npm install
npm run build
npm run preview -- --host 0.0.0.0
```

انشر محتويات مجلد `dist/` على استضافة تدعم تطبيقات Vite الثابتة، واضبط إعادة توجيه المسارات إلى `index.html` لأن التنقل بين الصفحات يستخدم مسارات من جانب العميل.

### ملاحظات تشخيص الصفحة البيضاء
- تأكد من أن الحزم ثبتت بنجاح؛ انقطاع الشبكة أثناء `npm install` قد يترك المشروع بلا تبعيات.
- لا تفتح `index.html` من تطبيق الملفات مباشرة.
- افتح Console/Terminal في بيئة التطوير وابحث عن أول رسالة `Failed to resolve import` أو `Uncaught Error`.
- أُضيف Error Boundary ليعرض رسالة قابلة للفهم عند حدوث خطأ React أثناء العرض، لكنه لا يعالج أخطاء البناء أو فشل تحميل الحزم.
- التقييمات والاقتراحات والمصادقة وقاعدة البيانات ليست خدمات خلفية مفعّلة في هذه النسخة.


## تنسيق الواجهة
تم دمج CSS داخل `src/main.jsx` في الثابت `GLOBAL_STYLES`، لذلك لم يعد المشروع يعتمد على ملف `src/styles.css` منفصل.


## نشر GitHub Pages
تم تضمين سير عمل GitHub Actions في `.github/workflows/deploy.yml`. ارفع المشروع إلى المستودع على الفرع `main` أو `master`، ثم من **Settings → Pages** اختر **GitHub Actions** كمصدر للنشر. سيبني GitHub المشروع وينشر مجلد `dist` تلقائياً. إعداد Vite يضبط مسار المستودع تلقائياً أثناء البناء، كما تضبط روابط التنقل لتعمل تحت مسار المستودع.
